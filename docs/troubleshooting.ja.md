## セットアップトークンが分からない

セットアップトークンは最初の管理者を作るまで使えます。次のどちらかで確認できます。

- サーバーの起動時のログ。`docker logs mars 2>&1 | grep token=` で探せます。
- データフォルダの `setup-token` ファイル。TrueNAS では、シェルで `sudo cat /mnt/tank/apps/mars/setup-token` を実行します（パスは環境に合わせてください）。

管理者がすでに作られている場合、トークンは削除されています。ログイン画面で、ユーザー名とパスワードでサインインしてください。

## permission denied が出る

データフォルダに書き込めないと、起動時のログに `permission denied` が出ます。MARS はデータフォルダに書き込む必要があります。

- Docker: イメージは uid 65532 で動きます。名前付きボリュームはそのまま使えます。ホストのフォルダをマウントする場合は、フォルダの持ち主を変えてください。

  ```sh
  mkdir -p data && sudo chown 65532:65532 data
  ```

- TrueNAS SCALE: `apps` ユーザー（uid 568）で動きます。データセットの持ち主と権限を、568 に合わせてください。手順は [TrueNAS SCALE での導入](install/truenas.ja.md) を参照してください。

ライブラリのフォルダは、MARS が読めれば十分です。書き込みは不要です。

## スキャンしても本が出ない

次の順に確認してください。

1. **フォルダが正しいか。** ライブラリの「フォルダ」が、本の入っているフォルダを指しているか確認します。Docker では、マウント先のパス（例: `/comics`）を指定します。
2. **拡張子が対応しているか。** 対応しているのは `.cbz`、`.zip`、`.cbr`、`.rar`、`.cb7`、`.7z`、`.pdf` です（[ライブラリとスキャン](libraries.ja.md#対応形式) を参照）。
3. **フォルダ名が `.` で始まっていないか。** 名前が `.` で始まるファイルとフォルダは、無視されます。
4. **除外パターンに一致していないか。** ライブラリの編集画面で、除外パターンを確認してください。
5. **読めるか。** MARS の実行ユーザー（Docker では uid 65532、TrueNAS では 568）に、フォルダとファイルの読み取り権限が必要です。
6. **解析に失敗していないか。** 管理 > メディア管理 の「エラー」「見つからない」タブで確認します。
7. **ゴミ箱に入っていないか。** 同じタブの「ゴミ箱」に、本やシリーズがないか確認します。ファイルが同じ場所に戻ると、次のスキャンで元に戻ります。

ファイルを追加したあとは、ライブラリの「スキャン」を押してください。

## シンボリックリンク

- ライブラリのルートフォルダがシンボリックリンクの場合は、リンク先をスキャンします。
- ルートの内側にあるシンボリックリンクは、たどりません。リンク先のフォルダや本は、スキャンされません。

リンク先の本を使いたい場合は、リンク先のフォルダをライブラリとして直接登録してください。または、ルートの直下にリンク先を置き換えてください。

## 監視が効かない

ファイルを追加や変更したあとに、自動でスキャンされない場合は次を確認してください。

- ネットワーク共有（SMB や NFS）: 共有のフォルダでは、ファイルの変更を検知できないことがあります。定期スキャンを併用してください。
- 監視の上限（Linux）: 監視できるフォルダ数には、OS の上限があります。上限に達すると、ライブラリの一覧に監視が動いていない理由が表示されます。

  Linux の上限を増やすには、`fs.inotify.max_user_watches` の値を大きくします。値は `524288` などです。TrueNAS SCALE では、**System > Advanced > Sysctl** に追加します。Docker の場合は、ホストで `sudo sysctl fs.inotify.max_user_watches=524288` を実行し、再起動後も残す場合は設定ファイルに書いてください。

監視が動かなくても、定期スキャンは動き続けます。

## スマートフォンにインストールできない

MARS をホーム画面に追加してインストールできるのは、HTTPS で開いている場合だけです。`http://192.168.1.10:25600` のような LAN 上の HTTP のアドレスでは、ブラウザで使えますが、インストールは表示されません。

HTTPS の設定は [Docker でのインストールの説明](install/docker.ja.md#https-とスマホへのインストール) を参照してください。Tailscale の `tailscale serve` を使う方法と、リバースプロキシで証明書を付ける方法があります。

## リバースプロキシ越しにログインできない

リバースプロキシ（Caddy、Traefik、nginx など）の内側で MARS を動かすと、次の設定が必要です。

- `Host` ヘッダーを元のまま渡してください。nginx では `proxy_set_header Host $http_host;` と書きます。`$host` を使うと、ポート番号（`:8443` など）が消えて、サインインに失敗します。
- `X-Forwarded-Proto` に、`https` を設定してください。nginx では `proxy_set_header X-Forwarded-Proto $scheme;` と書きます。
- 転送元のプロキシのアドレスを、`MARS_TRUSTED_PROXIES` に設定してください。
- 画面の更新に使う `/api/v1/events` では、バッファリングを止めてください。nginx では `proxy_buffering off;` を書きます。

## Mihon や OPDS アプリがつながらない

次の順に確認してください。

1. **機能が有効か。** 管理 > サーバー設定 の「連携」で、「OPDS」または「Komga 互換 API（Mihon）」が有効になっているか確認します。無効の場合、アドレスは見つからないと応答します。
2. **アドレスが正しいか。** OPDS は `http://HOST:25600/opds/v1.2/catalog`、Mihon は `http://HOST:25600/komga` です。
3. **サインインの情報が正しいか。** MARS のユーザー名とパスワード、または API キーをパスワードの欄に入力します。API キーの作り方は [ユーザーと権限](users.ja.md#api-キー) を参照してください。
4. **ユーザーの権限があるか。** 本を読むには「ページのストリーミングを許可」、ダウンロードには「ファイルのダウンロードを許可」が必要です。
5. **Mihon のトラッカーの場合。** トラッカーは Komga 拡張で一度サインインしたあとの Cookie を使います。先に拡張でサインインしてください。
6. **外部からの接続。** MARS の外から接続する場合は、HTTPS を使ってください。

それでも解決しない場合は、`docker logs mars` のログを確認してください。

## ログの見方

ログはコンテナーの標準出力に出ます。

```sh
docker logs mars
docker logs -f mars
docker logs --tail 200 mars
```

TrueNAS SCALE では、アプリの画面から **View Logs** を開いてください。

問題を調べるときは、`ERROR` や `WARN` の行に注目してください。`schedule`、`thumbnail`、`watch` などの名前が付いた行は、スキャン、サムネイル、ファイル監視の問題を示します。

## 不具合の報告

不具合は [GitHub の Issue](https://github.com/tabunugoku/MARS/issues) で報告してください。次の情報があると、原因を調べやすくなります。

- 使っている MARS のバージョン、またはイメージのタグ（例: `0.1.0`）。サインイン画面の下に「MARS」とバージョンが表示されます。ソースからビルドした場合は、ビルドしたコミット（例: `main@abc1234`）を書いてください。
- 実行環境（Docker、TrueNAS SCALE、リバースプロキシの有無など）
- 操作の手順と、期待した結果と実際の結果
- `docker logs mars` の該当する行

ログを貼るときは、ファイル名や個人の情報を消してください。
