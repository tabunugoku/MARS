# バックアップとアップグレード

この資料では、データフォルダの中身、バックアップと復元の手順、アップグレードの注意点を説明します。

## データフォルダの中身

MARS はデータフォルダ（Docker イメージでは `/data`）に次のファイルを書きます。

| パス | 内容 | 消えたときの影響 |
| --- | --- | --- |
| `mars.db` | データベースです。ユーザー、API キー、読書の進捗、コレクション、リーディングリスト、サーバー設定、メタデータの編集内容が入ります。 | 最も重要です。消えると、これらすべてが失われます。 |
| `mars.db-wal`, `mars.db-shm` | サーバーが動いている間だけ作られる、データベースの補助ファイルです。 | 通常は、サーバーを停止すると消えます。 |
| `thumbnails/` | 表紙のサムネイルです。アップロードした表紙の画像もここに保存されます。`thumbnails/jpeg/` には、OPDS と Komga 互換 API 向けの JPEG の写しがあります。 | アップロードした表紙の画像は失われ、再生成できません。それ以外のサムネイルは再生成できます。 |
| `cache/pages/` | アーカイブから取り出したページの一時的な写しです。上限は 2 GiB です。 | 再生成できます。 |
| `cache/page-thumbs/` | ページのサムネイルの一時的な写しです。 | 再生成できます。 |
| `listen-addr` | サーバーが起動するときに書かれるファイルです。ヘルスチェックに使われます。 | 次の起動で作り直されます。 |
| `setup-token` | 最初の管理者を作るまで存在する、セットアップトークンです。 | 管理者を作ったあとは削除されます。 |

本のファイルはデータフォルダには入りません。本のファイルはライブラリのフォルダにあります。MARS のバックアップには含まれないため、本のファイルは別に保管してください。

## 何をバックアップするか

| 対象 | 必要か |
| --- | --- |
| `mars.db` | 必要です。 |
| `thumbnails/` | 表紙の画像をアップロードしている場合は必要です。アップロードした画像は、ここにしかありません。 |
| `cache/` | 必要ありません。消えても、再生成できます。 |
| 本のファイル（ライブラリのフォルダ） | MARS の外で管理されているため、通常のバックアップ手段で保管してください。 |

キャッシュを外すと、バックアップの量を減らせます。表紙の画像をアップロードしていなければ、`thumbnails/` も外せます。ただし、サムネイルの再生成には時間がかかります。表紙を作り直す場合は、[ライブラリとスキャン](libraries.ja.md#サムネイル) を参照してください。

## 安全にバックアップする

MARS はデータベースを WAL モードで使います。動いている間に `mars.db` だけをコピーすると、まだ書き込まれていない変更が抜けることがあります。

安全な方法は次のどちらかです。

### 停止してコピーする

1. MARS を停止します。Docker なら、`docker stop mars` を実行します。
2. データフォルダを、丸ごとコピーします。`mars.db-wal` と `mars.db-shm` も含めてください。
3. MARS を起動します。`docker start mars` を実行します。

### ファイルシステムのスナップショットを使う

TrueNAS などでは、スナップショットを使えます。スナップショットを取る前に MARS を停止するか、データの書き込みが止まっている時間を選んでください。

TrueNAS でスナップショットを巻き戻す場合は、必ず MARS を停止してから行ってください。動いているデータベースのファイルを差し替えると、データが壊れるおそれがあります。

## 復元

1. MARS を停止します。
2. データフォルダを、バックアップの内容に置き換えます。`mars.db` と、あれば `mars.db-wal`、`mars.db-shm` を含めてください。
3. MARS を起動します。

復元のあとは、管理 > タスク でスキャンが動いていることを確認します。バックアップの後に追加された本は、スキャンで見つかります。

## アップグレード

### 手順

1. MARS を停止し、データフォルダをバックアップします（上の手順を参照）。
2. 新しいイメージを使うように、コンテナーを作り直すか、タグを変えます。
3. MARS を起動します。

MARS の起動時に、データベースの変更（マイグレーション）が自動で行われます。変更は、適用されていない分だけが順番に適用されます。

### 注意

- メジャーバージョンを上げる前は、必ずバックアップを取ってください。
- マイグレーションが失敗すると、サーバーは起動しません。ログにエラーが出ます。その場合は、バックアップから `mars.db` を戻して、ログの内容を確認してください。
- Docker のタグは、`1.0.0` のような完全な番号、`1.0`、`1`、`latest` が使えます。`latest` は、最新の正式版を指します。タグを固定したい場合は、番号を指定してください。

### ダウングレード

新しいバージョンのデータベースを、古いバージョンで使う手順は試験していません。古いバージョンに戻す必要がある場合は、アップグレードの前に取ったバックアップから `mars.db` を戻し、古いイメージを使ってください。
